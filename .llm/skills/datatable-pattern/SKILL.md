# DataTable Pattern with MobX

## Overview

Pattern for implementing a **headless DataTable** with **MobX controllers**. The DataTable provides no default UI - you must provide all UI components.

## Key Principles

1. **Headless**: No default styles or UI components
2. **MobX Controller**: Implements `IDataTableController<T>` interface
3. **Separate Columns**: Columns are defined separately from the controller
4. **Component Overrides**: All UI components must be provided (globally or per instance)
5. **Type Safety**: Full TypeScript support with strict types

## Template: DataTable Controller with ObservedQuery (Recommended)

**This is the recommended pattern** - Uses auto-generated ObservedQuery from hey-api.

```typescript
import { makeAutoObservable } from "~@/mobx";
import type { IDataTableController, ErrorInfo } from "~@/data-table";
import { type GetAllItemsV1Data, getAllItemsV1ObservedQuery } from "~@/api";
import type { Item } from "~@/models";

export class ItemsDataTableController implements IDataTableController<Item> {
  readonly tableId = "items-table";

  // Private ObservedQuery instance (auto-generated by hey-api)
  #query = getAllItemsV1ObservedQuery();

  constructor() {
    makeAutoObservable(this);
  }

  // Delegate to ObservedQuery
  get data(): Item[] {
    return this.#query.data?.data ?? [];
  }

  get total(): number {
    return this.#query.data?.total ?? 0;
  }

  get isLoading(): boolean {
    return this.#query.isLoading;
  }

  get isFetching(): boolean {
    return this.#query.isFetching;
  }

  get isError(): boolean {
    return this.#query.hasError;
  }

  get error(): ErrorInfo | null {
    return this.#query.error;
  }

  // Load data with query parameters
  async load(query: Partial<GetAllItemsV1Data>): Promise<void> {
    this.#query.load(query);
  }

  // Optional: refresh method
  async refresh(): Promise<void> {
    await this.#query.loadAsync();
  }

  // Optional: row click handler
  onRowClick = (row: Item): void => {
    console.log("Row clicked:", row);
  };

  dispose(): void {
    this.#query.dispose();
  }
}
```

**Key Points:**
- ✅ Use `#query` (private field) to store ObservedQuery
- ✅ Call `getAllItemsV1ObservedQuery()` to create instance (auto-generated)
- ✅ Delegate all getters to `#query`
- ✅ Type `load()` parameter with `GetAllItemsV1Data` (auto-generated type)
- ✅ Access response data via `this.#query.data?.data` (nested structure)
- ✅ No need for manual `runInAction`, `AbortController`, or error handling
- ✅ MobX reactivity is automatic

## Template: DataTable Controller with Mutations

```typescript
import { makeAutoObservable } from "~@/mobx";
import type { IDataTableController, ErrorInfo } from "~@/data-table";
import {
  type GetAllItemsV1Data,
  getAllItemsV1ObservedQuery,
  deleteItemV1ObservedMutation,
} from "~@/api";
import type { Item } from "~@/models";

export class ItemsDataTableController implements IDataTableController<Item> {
  readonly tableId = "items-table";

  #query = getAllItemsV1ObservedQuery();
  #deleteMutation = deleteItemV1ObservedMutation();

  constructor() {
    makeAutoObservable(this);
  }

  get data(): Item[] {
    return this.#query.data?.data ?? [];
  }

  get total(): number {
    return this.#query.data?.total ?? 0;
  }

  get isLoading(): boolean {
    return this.#query.isLoading;
  }

  get isFetching(): boolean {
    return this.#query.isFetching;
  }

  get isError(): boolean {
    return this.#query.hasError;
  }

  get error(): ErrorInfo | null {
    return this.#query.error;
  }

  async load(query: Partial<GetAllItemsV1Data>): Promise<void> {
    this.#query.load(query);
  }

  async deleteItem(itemId: string): Promise<void> {
    await this.#deleteMutation.mutateAsync({
      path: { id: itemId },
    });
    this.#query.invalidate();
  }

  get isDeleting(): boolean {
    return this.#deleteMutation.isPending;
  }

  dispose(): void {
    this.#query.dispose();
  }
}
```

## Template: DataTable Controller (with ViewModel)

**Use this pattern when you need to share data across multiple components.**

```typescript
import { makeAutoObservable } from "~@/mobx";
import type { IDataTableController, ErrorInfo } from "~@/data-table";
import { itemsPanelViewModel } from "~@/view-model";
import type { Item } from "~@/models";

export class ItemsController implements IDataTableController<Item> {
  readonly tableId = "items-table";

  // Reference to singleton ViewModel (ViewModel uses ObservedQuery internally)
  private vm = itemsPanelViewModel;

  constructor() {
    makeAutoObservable(this);
  }

  dispose(): void {
    // Cleanup if needed
  }

  async load(query: Partial<GetAllItemsV1Data>): Promise<void> {
    // Delegate to ViewModel
    await this.vm.load(query);
  }

  // Computed properties that delegate to ViewModel
  get data(): Item[] {
    return this.vm.items;
  }

  get total(): number {
    return this.vm.total;
  }

  get isLoading(): boolean {
    return this.vm.isLoading;
  }

  get isFetching(): boolean {
    return this.vm.isFetching;
  }

  get isError(): boolean {
    return this.vm.hasError;
  }

  get error(): ErrorInfo | null {
    return this.vm.error;
  }

  // Optional: row click handler
  onRowClick = (row: Item): void => {
    console.log("Row clicked:", row);
  };
}
```

**When to use this pattern:**
- ✅ Data is shared across multiple components (not just the DataTable)
- ✅ Need complex business logic or computed properties in ViewModel
- ✅ Multiple components need to coordinate around the same data

**When NOT to use this pattern:**
- ❌ Data is only used in the DataTable (use ObservedQuery pattern instead)
- ❌ No need for shared state (simpler to use ObservedQuery directly)

## Template: Columns Definition

```typescript
import type { DataTableProps } from "~@/data-table";
import { Badge } from "~@/ui";
import type { Item } from "~@/models";

export const getItemColumns = (): DataTableProps<Item>["columns"] =>
  [
    {
      accessorKey: "status",
      header: "Status",
      size: 100,
      cell: ({ row }) => {
        const status = row.original.status;
        const variant = {
          active: "success",
          pending: "warning",
          inactive: "secondary",
        }[status];
        return <Badge variant={variant}>{status}</Badge>;
      },
    },
    {
      accessorKey: "name",
      header: "Name",
    },
    {
      accessorKey: "category",
      header: "Category",
      size: 150,
    },
    {
      accessorKey: "createdAt",
      header: "Created",
      size: 180,
      cell: ({ row }) => new Date(row.original.createdAt).toLocaleString(),
    },
    {
      id: "actions",
      header: "",
      enableSorting: false,
      size: 50,
      cell: ({ row }) => (

      ),
    },
  ] satisfies DataTableProps<Item>["columns"];
```

## Template: Component Usage

```typescript
import { useMemo } from "react";
import { observer } from "~@/mobx";
import { DataTable } from "~@/data-table";
import { ItemsDataTableController } from "./ItemsDataTableController";
import { getItemColumns } from "./columns";
import type { Item } from "~@/models";

export const ItemsPage = observer(function ItemsPage() {
  const controller = useMemo(() => new ItemsDataTableController(), []);
  const columns = useMemo(() => getItemColumns(), []);

  return (
    <div>
      <h1>Items</h1>
      <DataTable<Item>
        controller={controller}
        columns={columns}
        showSearch={true}
      />
    </div>
  );
});
```

## StandardQuery Interface

The `load` method receives a `StandardQuery` object:

```typescript
interface StandardQuery {
  page?: number;           // Current page (0-based internally)
  limit?: number;          // Page size
  search?: string;         // Search query
  sortBy?: string;         // Sort field
  sortOrder?: "asc" | "desc";
  filters?: Record<string, unknown>;
}
```

## Two Controller Patterns

### Pattern 1: Controller with ObservedQuery (Recommended)
- **Recommended for most DataTables**
- Controller uses auto-generated `ObservedQuery` directly
- All data logic in one place (Controller)
- No need for separate ViewModel
- Type-safe with auto-generated types
- Automatic MobX reactivity
- No manual `runInAction`, `AbortController`, or error handling

**Use when:**
- ✅ Data is only used in the DataTable
- ✅ Need server-side pagination/filtering/sorting
- ✅ Want simplest possible implementation

### Pattern 2: Controller with ViewModel (For Shared Data)
- Controller delegates to ViewModel for data
- ViewModel uses `ObservedQuery` internally
- Data is shared across multiple components
- Controller is just a DataTable adapter

**Use when:**
- ✅ Data is shared across multiple components
- ✅ Need complex business logic or computed properties
- ✅ Multiple components coordinate around the same data

## Best Practices

✅ **DO:**
- **Use Pattern 1 (ObservedQuery)** - Recommended for most DataTables
- **Use private fields** - Store queries in `#query` (private field)
- **Use generated functions** - Call `getApiV1ItemsObservedQuery()` to create instances
- **Type parameters** - Use generated `GetApiV1ItemsData` type for `load()` parameters
- **Access nested data** - Response is often nested: `this.#query.data?.data`
- Implement `IDataTableController<T>` interface
- Use `makeAutoObservable(this)` in constructor
- Define columns separately from controller
- Use `DataTableProps<T>["columns"]` type for columns
- Use `satisfies` for type checking columns
- Memoize controller and columns in component
- Call `dispose()` to cleanup ObservedQuery

❌ **DON'T:**
- **Don't use public fields** - Use `#query` (private) not `query` (public)
- **Don't use Pattern 2 unless needed** - Only use ViewModel when sharing data
- Pass data to controller via constructor
- Put columns in the controller
- Forget to implement `dispose()` method
- Access data without null check (always use `?.` or `??`)
- Create controller inside render (use `useMemo`)
- Recreate columns on every render (use `useMemo`)

## Global Component Overrides

Set up global defaults to avoid repeating component overrides:

```typescript
// app/providers/AppDataTableProvider.tsx
import { DataTableConfigProvider, type DataTableComponentOverrides } from "~@/data-table";
import { TableView, Pagination, SearchInput, Loading, EmptyState, ErrorState } from "~@/ui";

const components: DataTableComponentOverrides = {
  TableView,
  Pagination,
  SearchInput,
  Loading,
  EmptyState,
  ErrorState,
};

export function AppDataTableProvider({ children }: { children: ReactNode }) {
  return (
    <DataTableConfigProvider
      value={{
        components,
        config: {
          defaultPageSize: 25,
          searchDebounceMs: 300,
        },
      }}
    >
      {children}
    </DataTableConfigProvider>
  );
}
```
